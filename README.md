# 用 GUI 自动化完成 MOOC 视频学习与随堂测验

> 课程作业提交版。这个程序不调用任何网站接口，也不破解登录：它**像人一样**看屏幕、读文字、
> 移动鼠标点按钮，把"看视频 + 做题"这套重复劳动自动化，并记录每一步的判据。

## 使用声明

本项目是**自动化与人机交互技术的课程练习**，用于学习"如何在没有 WebDriver、没有网站接口的
前提下，用截图 + OCR + 合成输入做流程自动化"，以及"如何为一个不可靠的视觉判据设计验证与
恢复机制"。

- 请只在**自己有权访问的课程**上使用，并遵守所在平台的服务条款与学校规定；
- 本项目**不绕过**任何学习要求：视频必须真播到位（不拖拽、不倍速），题目由模型作答且
  答完要经平台判定；
- 代码中的判定阈值都是在特定页面主题下实测的，**换课程/换平台需要重新量测**；
- 公开发布仅为课程作业展示，作者不对使用后果负责。

---

## 1. 目标与问题

在线课程的学习任务点通常要求：**视频必须真看完（平台要求 90% 时长，且禁止拖拽/倍速）**，
中途会弹出随堂测验，答对才继续。于是问题被拆成四件事：

1. 知道"现在该干什么"（播视频 / 答题 / 进下一节 / 已经全完成）；
2. 知道"视频到底在不在播"（画面静止 ≠ 暂停，静态讲义也能静止）；
3. 知道"题目长什么样、选项在哪、平台判对还是判错"；
4. 无人值守地跑完几十节，中途出错能自恢复，出事能留下可诊断的证据。

## 2. 运行环境（依赖清单）

### 必需

| 项 | 要求 | 说明 |
|---|---|---|
| 操作系统 | **Windows 10 / 11（64 位）** | 文字识别用的是系统自带的 `Windows.Media.Ocr`，通过 PowerShell 调用，原生只有 Windows 有 |
| PowerShell | 5.1 及以上 | 用于 OCR（`ocr_win.ps1`）与进程管理 |
| Python | **3.10 及以上** | 代码用了 `str \| None`、`tuple[int,int,int,int]` 等新语法 |
| 第三方库 | **仅 Pillow ≥ 10** | `pip install -r requirements.txt`。**没有** numpy / selenium / playwright / 第三方 OCR |
| 浏览器 | **Microsoft Edge** | 程序按窗口类名与进程名 `msedge` 找窗口；换其它 Chromium 需改 `BROWSER_PROC` |
| 屏幕 | 1920×1080 及以上，缩放建议 100% | 本项目在 **3840×2160 / 100%** 下实测；所有几何都是运行时实测的，换分辨率会自动适配，但极端的 DPI 缩放会影响 OCR 质量 |
| 权限 | **普通用户（Medium 完整性）** | Windows 的 UIPI 会**静默丢弃**低完整性进程发出的合成点击。程序在点击前会自检并打印 `input preflight: BLOCKED ...` 后拒绝继续 |
| 网络 | 仅答题时需要 | 调用 DeepSeek 的对话接口；不配密钥也能跑，但遇到题目会停在"求助"等人处理 |

### 不需要

管理员权限、GPU、数据库、任何网站的私有接口、任何浏览器插件或驱动（chromedriver 等）。

### 关于"看屏幕"这件事的硬性前提

程序运行时**独占鼠标键盘**：它会真的移动指针、真的按键。因此同一时刻只能允许一个实例在跑，
而且你要用电脑时应该先 `python control.py stop`。

## 3. 使用前准备（按顺序做一遍，大约 5 分钟）

程序是"看屏幕 + 动鼠标"的机器人，所以**屏幕上的状态就是你交给它的输入**。下面每一条都对应
程序里一个真实会用到的前提，漏了会在某个环节静默失败。

### 3.1 账号与课程

- [ ] 用**自己的账号**在浏览器里能正常打开超星/学习通，进到这门课的 **`学生学习页面`**
      （地址形如 `https://mooc1.chaoxing.com/mycourse/studentstudy?chapterId=...`）。
      注意：不是课程首页、也不是"我学的课"列表页——必须是那个"左边播放器、右边目录"的页面。
- [ ] 确认页面上三块都在：左侧**播放器能播**、右侧**"目录"可展开**（能看到小节列表）、
      页面上有"任务点 / 作业"之类的标记。这三块缺一块，程序就认不出页面。

### 3.2 浏览器（这一步最容易出错）

- [ ] 用 **Microsoft Edge**（程序按进程名 `msedge` 找窗口；Chrome 需改 `BROWSER_PROC`）。
- [ ] **只留课程这一个标签页**。多标签会让"喇叭图标"定位变复杂：每个标签都有自己的图标，
      程序要逐个比对才能找到"正在出声的那一个"。
- [ ] 在 Edge 设置里关闭**休眠标签页**（`设置 → 系统和性能 → 使用睡眠标签页保存资源` 关掉）。
      否则标签被挂起时视频/音频会被冻结，程序会反复尝试"续播"却无法推进。
- [ ] 窗口**最大化**，不要最小化。程序每轮会强制把它恢复并最大化，但**如果它被别的窗口
      完全遮住、或有置顶窗口压在上面**，截图读到的就不是课程页（程序会自检并报错，不会乱点）。
- [ ] 允许浏览器发出声音（系统音量不要静音）——"标签页喇叭图标"是判断"视频在不在播"的
      主要信号之一。

### 3.3 系统设置

- [ ] **显示缩放 100%**（`设置 → 系统 → 显示 → 缩放`）。多显示器且缩放不同时，建议把浏览器
      放在缩放为 100% 的主屏；分辨率 **≥1920×1080**。
- [ ] **关闭锁屏与睡眠**（运行期间锁屏 = 截图全黑 = 程序失效）：
      `设置 → 系统 → 电源` 里把"屏幕关闭/进入睡眠"都设为**从不**，并关闭"动态锁"。
- [ ] 关掉会**弹窗或抢前台**的东西：会议软件、更新提示、录屏工具。系统通知建议开"勿扰"。
- [ ] **用普通用户权限运行**（不要用管理员，也不要在受限沙箱里运行）。低权限进程发出的
      模拟点击会被 Windows（UIPI）**静默丢弃**——表现是"点了没反应"。
- [ ] 心里有数：程序运行时**独占鼠标键盘**。你要用电脑就先 `python control.py stop`。

### 3.4 代码侧准备

- [ ] `pip install -r requirements.txt`（只有 Pillow）。
- [ ] 打开 `auto_course.py`，把顶部的 **`LAST_SECTION`** 改成**你这门课的最后一节**编号
      （例如 `"20.5"`）。它是唯一的"课程结束"判据；不改的话它会一直往后找。
- [ ] （可选）配置答题模型；不配也能跑，但**遇到随堂测验会停下来求助**，等人处理：
      `$env:DEEPSEEK_API_KEY = "sk-..."`，或把密钥单独一行写进 `~/.mooc_llm_key`。
      自检：`python llm_answer.py`（会打印 `key found: True` 并能答出一道示例题）。

### 3.5 上线前的最后一道检查：只读模式

```powershell
python auto_course.py --dry-run
```

只做 INIT/OBSERVE：**读页面、打印判断，不点任何东西**。看它的输出是否与你的眼睛一致：

| 它打印的 | 应该等于 |
|---|---|
| `cursor=` | 当前真正所在的小节号 |
| `done=True/False` | 这一节的"任务点已完成"徽章在不在 |
| `quiz=True` + `options=N` | 屏幕上有没有题、有几个选项 |
| 没有任何 `CaptureError` / `BLOCKED` | 截图确实是浏览器、权限足够、能注入输入 |

对上了再正式跑。对不上就别跑——`--dry-run` 花你 10 秒，能省掉半小时的瞎猜。

## 4. 安装与运行

```powershell
pip install -r requirements.txt

# 可选：配置答题模型（不配则遇题即求助，不会瞎猜）
$env:DEEPSEEK_API_KEY = "sk-..."        # 或把密钥单独一行写进 ~/.mooc_llm_key
```

准备工作（第 3 节）做完后，按顺序：

```powershell
python auto_course.py --dry-run     # 只读自检：看清判断再动手
python control.py start             # 正式运行（runner + supervisor）
python status.py                    # 另开一个窗口看进度/速率/ETA
```

**第一次运行请盯 10 分钟**，确认三件事：① 它点开视频并真的开始播；② 遇到题目会停下来答题；
③ `status.py` 里的 `cursor` 会随着完成而前进。

停止：`python control.py stop`。
其它命令（查看它卡在哪、替它点一下、放行某一步、改终点）见 `docs/OPERATIONS.md`；
卡住时先跑 `python control.py pending` 看原因（会给出状态、游标和截图路径）。

## 5. 设计

### 5.1 为什么不用 Selenium / Playwright

平台能检测 WebDriver 特征，而且作业要求是"完成学习"，不是"绕过平台"。所以这里用**操作系统级
的输入合成**（`SendInput`）与**屏幕像素 + 系统 OCR**，对网站而言与真人操作同源，不引入
`navigator.webdriver` 之类的破绽，也不需要浏览器驱动。

代价是：程序必须"看得见"页面，所以**所有判据都要能从截图里量出来**。这决定了下面几条设计。

### 5.2 显式状态机（而不是一个大循环）

```
INIT ──► OBSERVE ──┬─► PLAY ──► OBSERVE ...            （视频没播完）
                   ├─► QUIZ ──► VERIFY ──┬─► OBSERVE   （答对/判不了）
                   │                     └─► QUIZ      （平台判错，换答案重试）
                   ├─► ADVANCE ──┬─► OBSERVE            （进入下一节）
                   │             ├─► DONE               （到最后一节）
                   │             └─► STUCK              （进不去，求助）
                   └─► STUCK                            （看不清/被挡住/需要人）
```

每一态只做一件事，并且**在日志里自己报名**（`[OBSERVE] done=... quiz=... cursor=...`），
所以任何一次停滞都能从日志定位到具体状态与判据。各状态的典型与最坏耗时见
`docs/STATE_MACHINE.md`。

### 5.3 三层看护（无人值守的关键）

| 层 | 职责 | 退出的条件 |
|---|---|---|
| `auto_course.py`（runner） | 干活：播视频、答题、验证、进下一节 | 到最后一节；或停在 STUCK 写"求助文件" |
| `supervise.py` | runner 挂了就重启；它停在求助时不动它 | 状态文件出现 `stopped` 标记 |
| `keeper.py` | supervisor 自己挂了就把它拉起来 | 看到"已完成"；或自身时限 |

求助通道：卡住时写 `auto_help/request.json`（含状态、游标、截图路径）+ 一个 `waiting` 标记，
由 `waiter.py` 负责被叫醒。人可以 `python control.py reply continue` 放行，或 `reply click x= y=`
替它点一下。

### 5.4 四个核心判据（都是被真实故障逼出来的）

1. **视频在不在播**：先看浏览器标签页的**喇叭图标**（有声音才在播）；取不到时**连读两次时间码**
   （3 秒内时钟前进=在播）。绝不用"画面静止"当暂停的证据——静态讲义会静止 20 分钟。
2. **题目存不存在**：靠**结构**（题型横幅 + ≥2 个选项圆点 + 提交按钮），不依赖 OCR 认选项字母
   （小字母经常读不出来）。答对与否靠**像素颜色**判断平台弹出的对错标记。
3. **有没有进入目标小节**：只认地址栏里的 `chapterId`，并与学到的小节 id 表比对。
   （曾经用过"标题匹配"，结果把标题相近的 `…（1）/（2）/（3）` 当成同一节跳过——教训见第 8 节。）
4. **这节是不是真完成了**：只认平台自己的 **`任务点已完成` 徽章**。程序绝不因为"视频播完了"
   就认为任务完成。

### 5.5 答题策略：不写规则

"绝对化表述就是错"这类规则会答错题。所以答题只有三级：
**答案缓存（只存平台认可过的）→ 大模型（附被拒选项清单，避免重复错答）→ 求助**。
模型给不出答案时停机求助，而不是猜。

## 6. 实测结果

- 完整跑完 **1.1 → 20.5（20 章 / 100 节）**，全程无人值守；一夜之间推进 25 节以上，
  稳定段速率约 **7–16 分钟/节**（视频本身 12–13 分钟）。
- 累计 **121 次答题判定**，其中 36 次被平台判错后由"被拒选项清单"换答案答对；
  **只有平台认可过的答案才会写进缓存**。
- 一轮夜间运行触发 **14 次求助**，全部定位到根因并修复（编号解析、播放器测量、窗口焦点、
  双实例、重试预算等），修复后同一类故障不再复现。

### 一个必须诚实写进报告的发现

程序自己判定了"课程完成"，但我用**独立核验脚本**（`verify_all.py`：逐节打开、读平台徽章）
复查后，发现 **5.2 / 6.5 / 7.3 / 18.3 这 4 节并未真正完成**——原因是导航校验的两次误判
（标题相似的 3 节被当成同一节；`chapter_ids.json` 里有一条 id 存错，触发了"已经在目标上"
的快捷判断）。这正是本作业最重要的一条经验：

> **"日志说完成"不等于"任务真的完成"。完成度必须由平台状态独立量测。**

修复方式是：把导航校验退回"只认 `chapterId` + 精确 id 表"，并用**剪贴板**（Ctrl+L、Ctrl+C）
读地址栏拿精确 id，不再用 OCR 读 URL（OCR 会把 `chapterId` 读成 `chapterld`、把 `=` 读成全角 `：`）。

## 8. 这个作业里踩过的坑（选）

1. **"点了播放键没反应"**：点击被 Windows UIPI 丢掉（进程完整性太低）。→ 点击前做预检，
   预检不过就明确报错，而不是无声失败。
2. **"时间码可见"不等于暂停**：控制条常驻是因为鼠标悬停在播放器上；照它去点会把**正在播**的
   视频点成暂停（实测 27 秒只走了 5 秒）。→ 改成时钟连读两次。
3. **平均红度找图标会全错**：浏览器标题栏会跟随页面主题染色，整条都"红"。→ 用强红像素
   （`r>170, r-g>55, r-b>25`）定位图标，再按实测宽度推图标右缘。
4. **两个窗口同时可见会逼死校验**：自动化宿主窗口占满屏幕、浏览器缩成小窗时，截图里两边都有，
   OCR 连宿主窗口里的文字都读进来。→ 强制浏览器铺满；截图后只保留落在浏览器窗口矩形内的文字。
   （注意：最大化是**异步**的，紧接着读窗口矩形会读到旧值。）
5. **重试预算被正常轮询吃掉**：状态机每轮都会进 PLAY，计数器不清零的话，第一次真正失败就直接
   放弃。→ 确认在播即清零。
6. **`Ctrl+R` 根本发不出去**：按键映射表缺 `r` 键，`chord("ctrl","r")` 抛 `KeyError`，
   看起来却像"快捷键无效"。→ 补全映射表。
7. **清理进程不能一刀切**：我曾用"杀掉所有 python 进程"来清理自己的残留实例，把同一台机器上
   别人正在运行的作业一起杀了。→ 必须按**命令行特征**过滤，只杀自己的进程。
8. **地址栏 OCR 不可靠**：`chapterId` → `chapterld`、`=` → `：`、URL 被截断。
   → 用剪贴板取精确 URL；并且**校验通过才允许覆盖**已保存的 URL 模板。

## 9. 已知限制

- 登录过期、验证码、平台改版、异常弹窗 → 都会停在求助，需要人处理（不会尝试绕过）。
- 视频必须真播（平台规则），所以单节耗时不可能低于视频时长。
- 只针对超星/学习通这套"左内容右目录"的课程页；换平台需要重写"读页面"那层（见 AI_CONTEXT.md
  的扩展点清单）。
- 程序运行时抢占鼠标键盘；你一动，平台会把视频暂停（程序会在一个轮询周期内续播）。
